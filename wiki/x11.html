Servidor X11 (pestañas X11)

Aplicaciones gráficas de Debian sin root: pestañas X11 embebidas y el servidor acompañante.

Las pestañas X11 muestran la pantalla de un servidor X que corre fuera de la interfaz de Terminal, en su propio proceso. La app no puede arrancar ese proceso por sí sola (necesita el APK en el classpath de app_process, dentro del mismo UID), así que te da un comando listo para copiar y pegar en una sesión de terminal: el companion.

Abrir una pestaña X11

En el menú lateral (drawer) toca X11. Se abre una pestaña nueva (icono de escritorio) con la barra de teclas extra habituales del terminal. Mientras no haya servidor, la pestaña muestra el estado «No X server is running» con el comando del companion y un botón Copiar comando.

Arrancar el companion

Pega el comando en una sesión de terminal normal de la app (la sesión Debian). Las sesiones enlazan /system de Android en lectura, así que pm y app_process son visibles desde el guest por rutas absolutas. El comando mostrado por la pestaña siempre refleja el id de paquete instalado; para este fork es: 

CLASSPATH=$(/system/bin/pm path --user 0 com.estrin217.terminal | head -1 | cut -d: -f2) \
  /system/bin/app_process / --nice-name=termux-x11 com.termux.x11.CmdEntryPoint :0

Notas del caso proot:

  • Las rutas son absolutas a propósito: dentro del guest el PATH es Debian puro y pm no alcanza por caminos relativos.
  • Si lo ejecutas en un shell Android de otro entorno (Termux clásico, adb shell), el mismo comando también vale: las rutas absolutas no cambian nada.
  • pm path calcula la ruta del APK instalado (no rompe ninguna actualización del fork).
  • app_process lanza com.termux.x11.CmdEntryPoint como proceso con el mismo UID que la app.
  • :0 es el número de display. Puedes poner otro (:1); la pestaña se reconecta sola al servidor que aparece.

Cuando el comando arranca, el proceso anuncia el display a la app por broadcast y la pestaña X11 pasa de la pantalla de estado a la pantalla del servidor: ahí dentro navegan las ventanas gráficas.

Usar las aplicaciones gráficas (caso Debian/proot)

Con el servidor corriendo, entra en la sesión Debian de la app y exporta el display antes de lanzar cada programa gráfico: 

export DISPLAY=:0

Algunas notas del entorno:

  • El servidor atiende las conexiones por el socket del display (:0); no requiere root ni TCP.
  • Si el programa se queja de libGL, acelera por llvmpipe (software): ver Limitaciones conocidas.
  • Las teclas extra (CTRL, ESC, etc.) de la pestaña X11 salen de la barra de la app; el teclado físico se manda al servidor tal cual.
  • El touch del servidor se pasa a las ventanas directamente; la emulación de gestos completa vive en la app standalone de termux-x11, no en esta pestaña.

Varias pantallas: etiquetas (tags)

Si necesitas dos servers distintos a la vez, etiqueta el companion con -tag: 

... com.termux.x11.CmdEntryPoint :1 -tag proyecto

Un servidor sin etiqueta atiende a la primera pestaña X11 sin etiqueta; un servidor con etiqueta va a la pestaña que la use. Si un servidor con etiqueta empieza a anunciarse antes de abrir la pestaña y no hay ninguna pestaña libre, se queda a la espera hasta que esa pestaña exista.

Cerrar y aclaraciones

  • Cerrar la pestaña X11 no detiene el servidor: vive en su propio proceso hasta que mates el proceso o escribas en él. Para reproducir ventanas nuevas, pega el comando de nuevo.
  • Si la pestaña dice «Disconnected from the X server», el companion murió o se detuvo; cópialo y arranca otra vez.
  • Si un build de este fork no trae la librería nativa (libXlorie), la pestaña avisa: instala el APK arm64-v8a de Releases.
  • Este es el integrado del fork ESTRIN217 de Terminal sobre termux-x11; sin afiliación con el equipo de Termux ni con X.Org.
